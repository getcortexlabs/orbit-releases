Create databases and Spaces on their own, and give your files a place of their own.

### Added

- Database and Space creation now offers Independent or In a project. Independent resources belong directly to the selected workspace and can be created before any project exists. Project resources retain their project and environment.
- Applications from different projects in the same workspace can explicitly connect to an independent database or Space. Private network access is limited to the selected application and resource, and is revoked when its last reference is removed.
- Spaces have a dedicated page that opens in Files, with bucket and storage information, S3 access and connected applications, Protection for backups, and Settings for service infrastructure and deletion.

### Changed

- Space creation emphasizes storage capacity and keeps service memory under infrastructure settings. Collection previews open directly in files when the current role can browse them.
- Workspace ownership is respected throughout inventories, permissions, backup destinations, file browsing, static publishing and notifications. Form errors preserve the draft and retry key; scope choices support keyboard navigation.

### Upgrading

- Existing databases and Spaces keep their project and environment. Choose Independent when creating a new resource to share it across projects in the same workspace.
- File browsing remains read-only. Upload, download and modify objects through an S3 client or application. Garage keys remain fixed for the lifetime of the Space.
- There is no automatic migration of existing resources and no automatic changes to hosted applications.

## Install or update

On a server with Ubuntu 22.04, 24.04 or 26.04, or Debian 12, on x86_64 or arm64:

```sh
curl -fsSL https://github.com/getcortexlabs/orbit-releases/releases/latest/download/install.sh | sudo sh
```

Servers on 0.1.22 or later can also update from Orbit updates in Settings.

Documentation: https://orbit.getcortexlabs.com
