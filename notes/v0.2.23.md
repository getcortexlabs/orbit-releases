Fix an intermittent console startup failure when opening or reloading Orbit.

### Fixed

- **Console startup.** Overlapping initial data loads could show "The console could not load" even when every API request succeeded. Initialization now starts through the signed-in session, and overlapping snapshots keep their own event buffers without clearing another request's state.
- **Retry and sign-out.** Late responses, errors and subscription callbacks from a stopped initialization no longer replace a newer successful load or repopulate cleared state. Current request failures still appear normally.

### Upgrading and validation

- No new metadata schema migration. This is the same application fix already validated on the private 0.2.23-beta.2 fleet; private installations stay on their channel.
- The full local suite passed 679 tests, including regressions for overlapping loads in both completion orders, event-stream reset, retry and sign-out. TypeScript and the production console build passed. Three reloads and the original concurrent-initialization reproduction passed against the installed production console, with no failed requests or page errors.
- Local validation was used at the maintainer's request; no successful full hosted CI attestation is claimed.

## Install or update

On a server with Ubuntu 22.04, 24.04 or 26.04, or Debian 12, on x86_64 or arm64:

```sh
curl -fsSL https://github.com/getcortexlabs/orbit-releases/releases/latest/download/install.sh | sudo sh
```

Servers on 0.1.22 or later can also update from Orbit updates in Settings.
