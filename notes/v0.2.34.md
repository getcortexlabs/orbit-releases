Start with the right process and keep image applications up to date from their registry.

### Added

- New projects can start as a web application, worker or job. Process cards explain each choice and support keyboard navigation. Jobs have a cron schedule and time zone, both shown before launch. Background processes do not ask for a public domain, port or HTTP health check.
- Applications created from images can check their registry for released versions. Updates within the current major version appear separately from later majors, which require reviewing compatibility. Catalog guidance remains available when a registry cannot answer.
- New Wiki.js installations use 3.4.0. Existing Wiki.js 2 projects are offered the final 2.x release and guidance for exporting into a new Wiki.js 3 installation.

### Changed

- Registry release checks compare moving-tag digests first and only list the relevant version window when needed, reducing registry requests.
- Switching process type preserves the configuration draft. Recoverable launch errors keep the schedule, commands and other choices for retry.

### Upgrading

- No metadata migration or automatic application upgrades. Existing services keep their process type; choose a different type when creating a new service.
- A job deployment prepares its schedule. Execute it with Run now or wait for the next scheduled time.
- Wiki.js 3 requires a separate installation and the upstream migration procedure for Wiki.js 2 data.

## Install or update

On a server with Ubuntu 22.04, 24.04 or 26.04, or Debian 12, on x86_64 or arm64:

```sh
curl -fsSL https://github.com/getcortexlabs/orbit-releases/releases/latest/download/install.sh | sudo sh
```

Servers on 0.1.22 or later can also update from Orbit updates in Settings.

Documentation: https://orbit.getcortexlabs.com
