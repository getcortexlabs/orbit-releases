### Added

- PostgreSQL's own memory follows the database's size. A PostgreSQL on CloudNativePG with 1 GB or more keeps a quarter of its memory as shared buffers, counts on three quarters as cache, and gets a sixteenth for maintenance and, for each sort, a share a hundred connections can all use at once. It used to run with PostgreSQL's defaults whatever memory it had: 128 MB of shared buffers and 4 MB for each sort. A new database starts with the settings and a memory change applies them.
- A database that already exists gets those settings with one reviewed restart. Its page shows **PostgreSQL's own memory** while it still runs with the defaults, and **Review the restart** opens the usual preview at the size it has. Updating Orbit restarts no database.
- A warning when a database has gone 15 minutes without being measured. It says which database, since when and what the measurement answered, follows the notification rules, and clears at the first measurement. A database that is being created, restored or upgraded, or whose pod is not running, does not count.
- The Servers page shows the main server as **Main server**, with **Control plane** and **Traffic entry**, and the server resource says `main` in the API. It used to read as a worker.

### Changed

- A build waits for the disk only when something waited on it for half or more of the last ten seconds. The bar was a fifth, which a busy and healthy server passes all the time.
- A measurement whose walk of the data directory was stopped now says `walking the data directory took more than 10 seconds` instead of `unexpected usage output`.

### Fixed

- Builds kept waiting on a server whose disk was busy and healthy. With disk pressure between 14 and 30 percent, above the old bar of 20, deployments stayed in the queue with nothing wrong.
- A server's card showed 0 databases while it ran databases and Spaces created outside a project. The count takes everything the workspace runs on the server.

## Install or update

On a server with Ubuntu 22.04, 24.04 or 26.04, or Debian 12, on x86_64 or arm64:

```sh
curl -fsSL https://github.com/getcortexlabs/orbit-releases/releases/latest/download/install.sh | sudo sh
```

Servers on 0.1.22 or later can also update from Orbit updates in Settings.

Documentation: https://orbit.getcortexlabs.com

## Validation

Hosted CI could not run: GitHub Actions did not start the full backend run because of account billing. The release was verified locally instead, recorded in the signed `VALIDATION.json`:

- Go tests and vet (56 packages), type checks, 847 TypeScript and 231 console unit tests, the contract, the docs build and the highlights.
- The race detector on Linux. The steps ran side by side, and under that load two tests failed on timing with no data race reported: one in replication and one in the AI machine agent's update. Alone they passed 3 of 3 and 5 of 5.
- 267 of 267 desktop journeys, and 374 of 376 journeys of the installed console at the first try. The other two passed on their second try: the new one for sizing PostgreSQL, which lost a keyboard focus while a button was disabled for a moment, and one for memory reservations that is known to fail under load. Both files passed alone on a quieter machine.
- The smoke test against the built binary, the pinned signature, the checksums, both binaries on amd64 and arm64, and the AI machine agent for macOS and Linux inside them.
- On a real K3s with CloudNativePG, at the release commit: sizing the settings of an existing PostgreSQL restarted it in place after 6 seconds in the same pod, with the data kept, and a new database started with the settings.
- Not run before publication: no installation was upgraded to this build first. A PostgreSQL with replicas sized in place, and the new warning produced by a real cluster, were not seen on real servers.
