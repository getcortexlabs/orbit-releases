### Added

- Pools of AI machines. A pool puts several machines behind one address: each call goes to a machine that has the requested model, preferring one with it already in memory and then the one with the most room left. Each machine takes a limit of calls at once, what Ollama runs in parallel by default, and a call waits in the pool's queue for up to its time before it gets `429` with `Retry-After`.
- Retries and checked answers for AI calls. Orbit tries a call again, on another machine when there is one, only while nothing of its answer has reached the application: when no machine took it, the machine dropped or Ollama answered `5xx`. A streamed answer that stops midway ends with an error line instead of looking complete, and an answer that is not streamed is kept until it is whole. When a call asks for a JSON Schema, with `format` or `response_format`, a text that does not match is tried again and ends as `422` with the validation errors. Answers carry `Orbit-AI-Attempts` and `Orbit-AI-Machine`.
- Use and speed of AI machines. A machine's page shows calls, errors, tokens per second per model, time to the first token and how busy it was; a pool's page shows time in the queue, refusals and which machine answered; the AI machines page shows each project's calls and tokens per day.
- Pull and remove models from the console. An administrator pulls a model by name with Ollama's progress, stops it, and removes a model after seeing which applications name it. The page shows the free disk, and Orbit stops a pull that does not fit. Applications still cannot manage models.
- Linux machines and other runtimes as AI machines. The same one-line command installs the agent as a systemd service on Linux, the machine reports its GPUs from `nvidia-smi`, and a machine can serve LM Studio, llama.cpp's server or vLLM through the `/v1` paths instead of Ollama.
- A direct stream for AI machines. With it on, each machine holds one HTTP/2 connection to Orbit over TLS 1.3 with a client certificate, on its own port, so calls start at once, tokens arrive as they are written and a call the application left stops in the same moment. It is off until an administrator turns it on, and a machine that cannot reach the port keeps using HTTPS.
- AI agents see and do much more through MCP. New tools read servers, a database in depth, variable names, domains, DNS zones, uptime, the status page, activity, costs and AI machines, and the latest log lines by period, level and deployment. After the person confirms, an agent creates a project or an environment, changes variables, scales, wakes, restarts, pauses and resumes an application, sets its operating hours, acknowledges or silences a warning and adds a note to an incident or resolves it.
- Restart and pause an application. Restart replaces the instances with new ones of the version it already runs, without building again. Pause stops an application by hand in any environment and frees its memory and CPU until someone resumes it. Both are on the application's page and in the API.
- Acknowledge and silence a warning from the console and the API, not only by replying to its alert email.
- Notes on an incident, signed and kept when the incident is rebuilt from new evidence, and Mark as resolved for an incident a person knows is over.
- A trash for the wiki. A deleted page leaves the library, the search and the export, keeps its text and every revision, and can be restored.
- `getReplication` answers `activeServerId`, so the API says which server runs the active Orbit after a failover.

### Changed

- Workspace admins write the General wiki. The admin role in at least one workspace is enough to create, edit, delete and restore its pages and to move folders between General and a workspace the person administers; it used to take Orbit's administrator. The same holds for API tokens and AI agents with the admin role.
- AI agents have their own place in Settings > Security, beside Secrets, API tokens and Sign-in providers.
- A call an AI machine was answering when it was removed, before any answer started, now moves to another machine of its pool. A single machine that is off answers `503` after three attempts instead of one.
- The `orbit-ai` agent speaks protocol 3 and updates itself on each platform. Agents from before 0.3.0 keep working over HTTPS with Ollama until they update, within an hour.

### Fixed

- Agents received catalog keys such as `warnings.databaseKernelPending.title` instead of text. Every answer an MCP tool reads now has its messages written out.
- `get_app_logs`, `get_deployment` and `get_operation` answered the oldest lines of a long log as if they were the latest. They follow the log to its end.
- Editing a wiki page through MCP moved it to the root of its collection, and editing a project's page was refused. An edit keeps the page where it is.
- Agents could not find pages kept in the General wiki.
- The shipped console showed the raw word `paused` in an application's status.
- The AI machines page heading lost the space between its two parts.

## Install or update

On a server with Ubuntu 22.04, 24.04 or 26.04, or Debian 12, on x86_64 or arm64:

```sh
curl -fsSL https://github.com/getcortexlabs/orbit-releases/releases/latest/download/install.sh | sudo sh
```

Servers on 0.1.22 or later can also update from Orbit updates in Settings.

Documentation: https://orbit.getcortexlabs.com

## Validation

Hosted CI could not run: GitHub Actions did not start the full backend run because of account billing. The release was verified locally and on a three server fleet instead, recorded in the signed `VALIDATION.json`:

- Go tests and vet (56 packages), type checks, 837 TypeScript and 229 console unit tests, the contract, the docs build and the highlights.
- The race detector on Linux. The steps ran side by side this time, and under that load two tests failed on timing with no data race reported: one in replication and one in the AI machine agent's update. Alone they passed 3 of 3 and 5 of 5.
- 364 of 364 journeys of the installed console and 266 of 267 desktop journeys. The one that failed, the theme kept after a reload in Settings, has been intermittent on main since before this release and passed 6 of 6 alone.
- The smoke test against the built binary, the pinned signature, the checksums, both binaries on amd64 and arm64, and the AI machine agent for macOS and Linux inside them.
- The fleet moved from 0.2.51 to 0.3.0, standbys first: the leader kept the lease without a warning and started a new replication log for the migration, and both standbys copied the database within five seconds.
- Not run on real hardware: the AI machine features were verified against fake machines, as no AI machine is connected to this fleet.
