PostGIS and pgvector for PostgreSQL, an application's image you can change in place, and installations that stop at the first failure.

### Added

- PostgreSQL databases on CloudNativePG can have PostGIS and pgvector, chosen at creation or added later under Resources. pgvector restarts nothing. PostGIS moves the database to the PostGIS image of the same PostgreSQL release with one restart, and the previous image is put back if the database does not return.
- Backups record the extensions of their database. Restore tests and masked preview copies run on an image that carries them, and row counts leave out the tables an extension owns.
- An application's image and registry credential are edited in its settings. Another tag of the same repository needs a developer; another repository or credential needs an admin.
- Compose files and catalog entries that use PostGIS or pgvector images become a managed PostgreSQL with that extension.

### Fixed

- A catalog or Compose installation stops at the database that failed, shows what the machine reported and continues from that step after a retry. Applications that read from that database wait for it instead of failing with a second error.
- Release builds check that the pinned Mavis patches are applied, before and after building the console. A build with another pnpm version could remove the fix that releases the page after a sheet closes.
- The project workspace no longer scrolls sideways for a moment on phones when Variables opens.
- The private Nuxt console proxies every API operation. Its list is now generated from the contract; 49 newer operations were missing from it.
- The server field of the new database form shows its label.

### Upgrading

- No metadata migration. Existing databases keep their image and do not restart.
- A PostgreSQL database where an extension was created by hand keeps working. Add the same extension on the database's page so Orbit records it and tests its backups on the right image.

## Install or update

On a server with Ubuntu 22.04, 24.04 or 26.04, or Debian 12, on x86_64 or arm64:

```sh
curl -fsSL https://github.com/getcortexlabs/orbit-releases/releases/latest/download/install.sh | sudo sh
```

Servers on 0.1.22 or later can also update from Orbit updates in Settings.

Documentation: https://orbit.getcortexlabs.com
