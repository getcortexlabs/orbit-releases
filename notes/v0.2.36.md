Deliver images at the size each screen needs, charge with Pix from your applications, and keep containers healthy on Ubuntu's newest kernels.

### Added

- A Space can deliver its images resized and compressed. Ask for a width, height, fit and format in the address, and Orbit picks the lowest quality that still looks the same, measured with SSIMULACRA 2, in AVIF, WebP or JPEG. Presets, signed links and a cache keep it fast and under your control.
- Scoped secrets for the installation, a workspace or a project, granted to selected projects and environments. Applications bind them by reference, and rotating or revoking one keeps a rollback from bringing back the old value.
- Applications can create one-time Pix charges and recurring Pix checkouts through Orbit, with their own AbacatePay account or one their project shares.
- The API keeps a project's server-driven interface sources, snapshots and builds, the groundwork for SDUI. There is no screen for it yet.

### Changed

- New PostgreSQL databases are created on PostgreSQL 18. PostgreSQL 19 waits until CloudNativePG supports it.
- PostgreSQL 16, 17 and 18 move to 16.16, 17.12 and 18.7, which fix several security issues.
- The mailbox reads well at every width. Checkboxes, spacing, focus rings and crowded controls were fixed across both consoles.
- The English and Portuguese guides keep the same sections, and the docs build checks it.

### Fixed

- On Ubuntu 26.04's newer kernels, AppArmor stopped a container's processes from signaling each other, so PostgreSQL could not finish recovering after an abrupt stop. Each server's agent now loads containerd's corrected profile, which keeps AppArmor on for every container.
- Database pages report instance readiness during recovery, and servers that host databases warn about a newer installed kernel and about blocked PostgreSQL signals.
- Backup verification uses its own scratch pod each time and cleans it up even when the check fails.
- The confirmation of a major database upgrade responds to the click it was given.

### Upgrading

- Existing PostgreSQL databases keep their major version. Databases on 16 or 17 move to 16.16 or 17.12 the next time Orbit applies a change to them, which restarts them once.
- A PostgreSQL instance that was already stuck in recovery before this update needs one restart. The servers guide explains it under Containers and AppArmor.

## Install or update

On a server with Ubuntu 22.04, 24.04 or 26.04, or Debian 12, on x86_64 or arm64:

```sh
curl -fsSL https://github.com/getcortexlabs/orbit-releases/releases/latest/download/install.sh | sudo sh
```

Servers on 0.1.22 or later can also update from Orbit updates in Settings.

Documentation: https://orbit.getcortexlabs.com
